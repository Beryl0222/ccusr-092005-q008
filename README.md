# 美术馆文创权利协作

公立美术馆文创产品**创意 → 审批 → 生产 → 退市**全链路协作后端。针对“已打样
才发现入藏手续不含复制与商业改编权、群聊追授权导致错误版本流入生产”的事故，
把元素引用、四门审核、许可边界、变更分级复审、撤回/改期分实例处置、合作方
信息隔离与成品溯源落成可执行的领域核心。

完整设计见 [`DESIGN.md`](DESIGN.md)。

## 模块

- `project_data.py`：读取并校验 `fixtures/seed.json`（作品、元素权利、合作方、展览）。
- `museum_collab/`：
  - `model.py` — 角色、四道审核门、变更影响矩阵、许可四维、实例状态与处置策略枚举；
  - `codec.py` — 规范化 JSON 与 SHA-256 内容/链式哈希；
  - `store.py` — 只追加事件日志、哈希链、乐观并发控制；
  - `repository.py` — 目录、提案聚合、元素占用台账的事件投影；
  - `access.py` — 按角色裁剪的信息视图（合同正文、内部沟通隔离）；
  - `system.py` — 用例服务：立项、修订、四门审批、许可/占用、打样/放行、撤回/改期、溯源。
- `tests/`：41 个 unittest，覆盖题述全部场景。

## 校验

```bash
python3 -m unittest discover -s tests
# 或
python3 -m pytest tests/
```

## 核心规则速览

- 提案必须标明**哪件作品的哪些元素**、以**复制还是商业改编**方式使用；
- 学术、权利、公益、经营**四门分立**，角色不可越权；无生效许可不得打样/量产；
- 图案/材质/渠道等变化按**变更影响矩阵**只重启必要的门，旧许可按需失效或沿用；
- 许可显式表达**数量（累计）、地区、渠道、期限、用途**，事件中只留合同编号与哈希；
- 权利人撤回或开幕改期后，按**未生产/在途/已售/仅展宣**分别处置，旧决定只追加不覆盖；
- 并行打样放行、排他占用阻断、同一元素**先量产者得**；
- 合作方只见本机构环节，**合同正文不对普通运营与合作方开放**；
- 策展人可对任一上市产品完整回查原作、沟通、批准版本与当前权利边界，并可验链防篡改。
